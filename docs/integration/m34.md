# MBooru: M34 integration

MBooru keeps its existing Android application ID, signing identity, multi-engine networking, tiled image viewer, Media3 player, WorkManager transfer queue and BGSU theme. The primary search screen has direct Favorites and Settings buttons, without a bottom bar or overflow menu. Favorites contains the shared library. Site switching remains in the side panel, available by edge swipe or Settings → Side panel; site management is inside Settings. The navigation drawer retains engine-supported pools, tags, artists, history and existing contextual tools. No removed reverse-search provider or retired preset is restored.

## Rule34

Sites includes Rule34 at `https://api.rule34.xxx/`. Connect with your own positive numeric user ID and API key from the site's account options. Both fields accept copied `user_id=…&api_key=…` parameters. An empty key during editing retains the stored key. Save stores credentials through MBooru's encrypted credential vault; Test makes an authenticated request; Disconnect removes the connection without deleting the local library. An existing custom configuration under either Rule34 hostname keeps its ID and credentials. Explicitly saving its Rule34 connection selects the dedicated adapter.

Rule34 uses the shared OkHttp/Retrofit infrastructure, HTTPS, no API redirects, the required Referer, no-store responses and bounded API bodies. Blank/null, non-array and malformed responses are errors, rather than empty success. Plain tags, exclusions and simple wildcards are checked against returned metadata; complex grouping operators remain server-owned. Latest, Random and Highest score use the service's sorting operators. Rule34 does not expose unsupported pools, artists, comments or remote-favorite writes.

Search supports explicit submission, optional 700 ms debounce, clear/cancel/refresh, history, active tag chips, rating and sort selection, suggestions, paging and per-site query/scroll restoration. Rule34 recommendation tags come from actual fetched random post metadata; other engines use recently cached post tags. Recommendations require available metadata and are not a fabricated live feed. Returning to an existing query reuses its cached paging session without repeating the initial auto-refresh; explicit Refresh still fetches again. Terminal page state is retained in the existing cursor table. Global Safe only permits General/Safe and blocks Questionable, Explicit and unknown ratings before thumbnails and viewer pages render. Original rating strings are retained.

## Local library and migration

Schema 12 adds `local_likes`, `named_collections`, `collection_memberships` and the default-true `saved_posts.is_saved` column. Room's explicit generated 11→12 migration preserves old saved snapshots as explicit saves; upgrading users' new tables begin empty. Earlier migration chains remain supported without destructive fallback. Site IDs and remote post IDs jointly identify artwork. Local saves, likes, collections and remote favorites have separate state. Removing a save or collection membership does not remove artwork referenced elsewhere.

Saved supports source filters, score/date ordering, collection creation/rename/deletion, multi-collection membership, local likes and opening artwork through the shared viewer without switching the globally selected site. Collection names are trimmed, case-insensitively unique, limited to 40 characters and cannot be blank or `All saved`. Metadata can remain available offline; media still requires cache or network access.

Saved → Export library creates `MBooru-library` version 1 JSON containing credential-free site configuration, owned artwork metadata, likes and collections. Saved → Import MBooru / M34 previews and validates a document before an atomic transaction. Repeated imports merge identities and case-insensitive collection names; existing accounts and site configuration remain local. Limits: 8 MiB per document, 10,000 artwork/like records, 1,000 collections, 100,000 memberships. Unreferenced retained metadata is omitted. This document does not embed downloaded media, credentials or raw preference files. Existing site-only backup imports remain supported in site management.

M34 uses another Android application sandbox and Keystore; MBooru cannot directly read it. The companion exporter is available in [M34 PR 1](https://github.com/mattzilla30/M34/pull/1). Install its signed M34 2 / code 12 update, open Settings → Library transfer → Export, then select that file in MBooru Saved → Import. It preserves real Rule34 saves, likes and collection memberships, excludes API secrets and leaves M34's library untouched. Demo artwork stays in M34. Likes without saved metadata import as unresolved Rule34 identities: unknown ratings stay hidden in Safe only and unavailable media receives an explanation. Encountering that post again repairs the metadata. Reconnect Rule34 in MBooru separately.

## Viewer, downloads and privacy

The existing large-image, pinch/double-tap, immersive, paging and video lifecycle implementation remains shared. Viewer controls add local likes/collections and a distinct remote-favorite action only for engines that support it. Download quality choices use the existing persistent WorkManager/SAF path and preserve the configured destination. A default 4 GiB transfer limit can be changed to 256 MiB, 1 GiB, 4 GiB or 8 GiB. Both known-length and streamed transfers enforce it; failure remains visible with retry controls. Transfer deduplication hashes the artwork source, final filename and destination scope, so repeated taps cannot create duplicate active transfers even when SAF allocates different temporary files. Safe filenames, cancellation, resume validation and partial-file publication are reused. WorkManager receives protected capabilities, not raw credentials.

Optional App lock uses Android's configured PIN/password/pattern, requires a secure device lock before enabling, hides content while locked and clears its in-memory grant on backgrounding. No new account synchronization, ads, billing or analytics are introduced.

## Compatibility and attribution

MBooru remains Kotlin/Compose Material 3/Room, minimum API 21, target API 36, with the existing native ABIs. No M34 API 37 or ARM64-only requirement was imported. Version 7 / code 1380 is an integer version increase. Build using the checked-in wrapper and documented JDK 21/Android SDK setup.
